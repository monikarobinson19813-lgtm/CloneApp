# CloneApp Slack Router

The Slack Router turns the CloneApp Slack workspace into the visible coordination layer for autonomous departments while GitHub remains authoritative.

## Transport

Initial deployment uses Slack **Socket Mode**.

Advantages:
- low-latency bidirectional events;
- no public inbound HTTP endpoint required;
- well suited to an always-on private orchestrator;
- can later switch to HTTP Events API if desired.

## Required Slack app setup

Create a dedicated Slack app/bot for the CloneApp engineering system.

Recommended credentials:
- `SLACK_BOT_TOKEN` — bot token.
- `SLACK_APP_TOKEN` — app-level token with Socket Mode connection permission.

Minimum capabilities depend on enabled features.

For the current router:
- send messages;
- read approved private CloneApp channels;
- resolve channel membership/listing.

For autonomous private-channel creation later:
- permission to create/manage private channels.

Keep scopes minimal and add them only when a feature requires them.

## Runtime

Install the optional Slack dependency:

```bash
pip install -e 'orchestrator[slack]'
```

Environment:

```bash
export SLACK_BOT_TOKEN='xoxb-...'
export SLACK_APP_TOKEN='xapp-...'
export CA_SLACK_STATE_DB=/var/lib/cloneapp/slack.sqlite3
```

Start:

```bash
ca-slack-router
```

## Routing contract

Structured messages begin with one of:

```text
[TASK]
[STATUS]
[QUESTION]
[HANDOFF]
[DECISION]
[BLOCKER]
[EVIDENCE]
[INCIDENT]
[DONE]
```

Optional routing metadata:

```text
To: qa
ISSUE #28
```

Examples:

```text
[HANDOFF] ISSUE #28 — storage isolation ready
To: qa

Commit: abc123
Requested tests: prefs/db/files/delete
```

```text
[QUESTION] ISSUE #31 — provider authority collision
To: architecture

Need decision between route A and route B.
```

## Loop prevention

The router:
- ignores messages generated by bots;
- ignores its own user id;
- persists Slack event ids and rejects duplicate deliveries;
- uses AGENT_COMMUNICATION.md exchange budgets for future agent-to-agent sessions.

## Owner messages

Unstructured human messages are intentionally not treated as machine routing commands.

The next stage connects those owner messages to the provider gateway so a department agent can answer in the same Slack thread.

## Dynamic channels

Dynamic channel creation is governed by AGENT_COMMUNICATION.md and Issue #27.

The Slack bot will eventually create channels such as:

```text
cloneapp-issue-28-storage-isolation
cloneapp-incident-07-emulator-flake
cloneapp-release-v0-1
```

Every dynamic channel must be linked to a GitHub issue/PR/ADR and have an explicit archive rule.
